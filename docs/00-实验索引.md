# 00 — 实验索引

## 目的

本索引是组件实验工厂的第一入口。所有候选组件先进入矩阵，再进入一个独立实验；实验输出证据和能力卡，最后由主仓库批准是否装配。

## 实验顺序

1. RB-FX-001：Python 标准库能否覆盖 Data/Core 的确定性底座；
2. RB-FX-002：Pydantic 是否适合边界合同而不污染 MALF 领域核心；
3. RB-FX-003：FastAPI + Uvicorn 是否能提供 GET/HEAD-only 本地 Viewer；
4. RB-FX-004：pytest 是否能承载单元、合同、故障注入和退出码证据；
5. RB-FX-005：Playwright 是否能在本机完成三视图和无外部请求验收；
6. RB-FX-006：比较 uv 与标准 venv/pip，不把包管理器变成运行时依赖；
7. RB-FX-007：比较 ECharts、Lightweight Charts 和无第三方图表。

## 证据路径

每个实验的机器证据位于 `evidence/<experiment-id>/`，人工摘要位于 `docs/03-试验记录.md`。临时环境、浏览器缓存和 `node_modules` 不提交。

## 统一结论格式

每个实验必须输出：

```text
status: candidate | trial-running | trial-passed | selected | deferred | rejected
version:
license:
command:
result:
limitations:
assembly_recommendation:
```

## 主系统装配条件

只有在以下条件同时满足时，主仓库任务才可以提出装配：实验通过、许可证可接受、版本可复现、离线/只读边界通过、失败有回滚、能力卡已归档、主仓库任务计划获得批准。`trial-passed` 本身不等于 `selected`。
