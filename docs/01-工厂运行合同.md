# 01 — 工厂运行合同

## 1. 隔离

工厂可以使用自己的 `.venv`、`node_modules`、临时目录和 fixture。所有产物必须留在 `J:\asteria-riskbench-factory` 内；禁止向主仓库和七个只读参考目录写入。

## 2. 数据

禁止用真实 TDX 或 MALF 文件作为首批组件实验输入。`.day` fixture 必须由实验自己生成，并标注为 synthetic fixture。真实数据资格由主系统 G0/G1 门禁负责，不由组件实验替代。

## 3. 网络

安装阶段可以访问官方包索引和上游官方发布源；运行时 smoke test 必须离线或仅访问本地 `127.0.0.1`。Viewer 页面不得依赖 CDN、遥测或远程字体。

## 4. 权限

- 构建/实验代码可以写工厂自身临时目录；
- Viewer 实验只能读已发布 fixture；
- 任何写方法必须收到 405；
- 任何读不到当前快照的情况必须显式失败，不能静默选择旧快照；
- 所有实验结束后可删除 `.venv`、`node_modules` 和证据临时文件并重建。

## 5. 证据

证据必须包含运行时间、Windows/Python/Node 版本、包版本、命令和退出码。人工结论不得超出机器输出。

## 6. 与主仓库的门禁

本工厂只允许验证“能力”；它不允许直接创建主仓库业务骨架，不允许改写 MALF 定义，不允许提升 `research_only` 数据为 `verification_only` 或 `operational`。
