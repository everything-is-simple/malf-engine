# 04 — 主系统装配建议

截至本文件初始创建时，工厂已建立候选和实验，不自动批准主系统装配。建议的装配顺序是：

1. Python 标准库：优先作为 Data/Core/Range 的无框架底座；
2. Pydantic：仅边界合同；
3. FastAPI + Uvicorn：仅只读 Viewer 服务；
4. pytest：所有主系统 TDD 任务的开发依赖；
5. Playwright：开发/验收依赖，不进入生产运行时；
6. uv：只有在 Windows 3.10、锁定、离线重建和小主机迁移证据成立后，才作为开发工具批准；否则用 venv/pip；
7. 图表：v0.1 先保留原生 HTML/CSS/SVG；ECharts 与 Lightweight Charts 只在任务明确需要复杂图表并有独立门禁后评估。

### 禁止的捷径

- 不从实验目录复制代码到主仓库；
- 不因 FastAPI 能启动就宣布 Viewer 完成；
- 不因 npm 包能安装就宣布图表选型完成；
- 不因某组件开源就忽略许可证、包体积、离线和供应链；
- 不把“工厂通过”写成“主系统批准”。

### 下一批准点

审核主仓库的 `TECH-STACK`、组件台账和工厂证据；批准后，才可以把指定 `selected` 组件纳入具体任务实现计划。前端/图表、uv、隧道仍应保持独立评审，不随主路径默认启用。
